# Skill Definition Template

이 템플릿은 하네스가 생성하는 각 스킬 파일의 표준 형식이다.

## 템플릿

```markdown
---
name: {skill-name}
description: >
  {적극적 트리거 설명. 스킬이 하는 일 + 구체적 트리거 상황을 모두 기술.
  "~해야 하는 경우 반드시 이 스킬을 사용할 것" 포함.}
---

# {Skill Name} — {목적}

{도메인}에서 {작업}을 수행하는 스킬.

## 실행 조건
이 스킬은 다음 상황에서 반드시 실행한다:
- {트리거 조건 1}
- {트리거 조건 2}

## 워크플로우
### Step 1: {단계명}
1. {액션}
2. {액션}

### Step 2: {단계명}
1. {액션}
2. {액션}

## 원칙
- {원칙 1 — 이유와 함께}
- {원칙 2 — 이유와 함께}

## 검증
- [ ] {검증 항목}
- [ ] {검증 항목}

## 참고
- {참고 사항}
```

## 예시: 리서치 하네스의 analyze 스킬

```markdown
---
name: analyze
description: >
  수집된 리서치 데이터를 분석하고 종합 보고서를 작성. analyst가 수집한 원시 데이터를
  입력으로 받아 체계적으로 정리하고 인사이트를 도출. 리서치 결과 정리, 데이터 종합,
  인사이트 추출이 필요할 때 반드시 이 스킬을 사용할 것.
---

# Analyze — 리서치 데이터 분석 및 종합

리서치 데이터를 체계적으로 분석하고 실행 가능한 인사이트를 도출하는 스킬.

## 실행 조건
- analyst의 수집 데이터가 `_workspace/01_analyst_findings.md`에 저장된 경우
- 여러 출처의 데이터를 종합해야 하는 경우

## 워크플로우
### Step 1: 데이터 수집 및 분류
1. `_workspace/01_analyst_findings.md` 읽기
2. 데이터를 출처 유형별(공식/미디어/커뮤니티)로 분류

### Step 2: 교차 검증 및 종합
1. 출처 간 일치/충돌 식별
2. 신뢰도 가중치를 적용한 종합 결론 도출

### Step 3: 보고서 작성
1. 실행 가능한 인사이트 도출
2. `_workspace/02_analyzed_report.md`에 저장

## 원칙
- 상충되는 정보는 삭제하지 말고 논쟁점으로 기록한다 — 읽는 사람이 판단하게 하라
- 모든 주장에는 출처와 신뢰도 등급(High/Medium/Low)을 명시한다
- 결론은 "~할 가능성이 높다", "~한다" 등 명확한 언어를 사용한다

## 검증
- [ ] 모든 주장에 출처가 명시되었는가?
- [ ] 상충 정보가 논쟁점으로 기록되었는가?
- [ ] 실행 가능한 인사이트가 3개 이상 도출되었는가?
```

## Description 작성 원칙

1. **Pushy하게**: "이런 경우 반드시 이 스킬을 사용할 것" 포함
2. **구체적 트리거 포함**: "~해야 하는 경우", "~가 필요할 때"
3. **스킬 설명 + 트리거 상황**을 모두 기술
4. **near-miss 배제**: 유사하지만 이 스킬이 아닌 경우와 구분 (예: "이미지 생성" vs "이미지 분석")

## SKILL.md 본문 원칙

| 원칙 | 설명 |
|------|------|
| **500줄 제한** | 넘으면 references/로 분리 |
| **Why 우선** | "NEVER" 대신 "~하면 안 되는 이유" 설명 |
| **명령형** | "~한다", "~하라" |
| **일반화** | 특정 예시 오버피팅 금지 |
